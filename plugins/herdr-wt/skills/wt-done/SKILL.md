# 작업을 끝내고 정리한다

**순서가 고정이다** — 뒤로 갈수록 되돌릴 수 없고, 마지막 단계는 이 세션을 함께 종료한다.

| 순서 | 하는 일 | 되돌릴 수 있나 |
|---|---|---|
| 0 | 사전 점검 + 승인 | 예 |
| 1 | PR 머지 | 아니오 |
| 2 | 저장소 지침의 마감 절차 | 예 |
| 3 | pane 정리 (기본 생략) | 예 |
| 4 | worktree 제거 | 아니오 — **이 세션이 함께 종료된다** |

**묻는 것은 0단계 한 번뿐이다.** 승인을 받으면 1~4단계는 되묻지 않고 끝까지 간다. 단 4단계 직전 재확인에서 0단계와 다른 것이 나오면 멈추고 묻는다.

## 저장소 지침

`.claude/wt.md` 가 있으면 먼저 읽고, 각 단계에서 관련 지시를 따른다 — 이슈 트래커 마감, 머지 뒤 후속 작업, 저장소 고유 점검처럼 저장소마다 다른 것이 거기 있다. 지침은 단계를 더하거나 값을 정할 뿐, **단계의 순서, 0단계 승인, 4단계 재확인은 바꾸지 못한다.**

없으면 base 는 `develop`, 이슈 트래커는 없는 것으로 진행한다.

**이슈 식별자가 필요하면 브랜치명에서 되돌린다.** 브랜치는 `<종류>/<슬러그>-<주제어>` 이고 슬러그는 식별자에서 `-` 를 떼고 소문자로 만든 값이다 — 되돌린 값이 실제 이슈와 맞는지 0단계에서 확인하고, 맞지 않으면 승인 질문에 함께 묻는다.

## 0. 사전 점검 — 물을 기회는 여기뿐이다

4단계가 세션을 끝내므로 **시작 전에 전부 조사하고 한 번에 묻는다.**

| 점검 | 정상 | 아니면 |
|---|---|---|
| 현재 브랜치의 PR | 있고 `OPEN` | 없거나 `CLOSED` 면 멈추고 묻는다. `MERGED` 면 1단계를 건너뛴다 |
| `mergeable` | `MERGEABLE` | `CONFLICTING` 이면 머지되지 않는다. `UNKNOWN` 은 아래를 따른다 |
| 저장소 머지 방식 | 허용 방식 확인 | 1단계가 이 값으로 정한다 — squash 가 허용되면 squash, 아니면 허용되는 것. 허용되지 않은 방식은 거부된다 |
| CI·리뷰 | 비었거나 통과 | 실패가 있으면 멈추고 묻는다. 진행 중이면 잠시 뒤 재조회하고, 그래도 진행 중이면 승인 질문에 적는다 |
| `git status` | 빈 출력 | 미커밋·untracked 는 worktree 와 함께 사라진다 |
| 미푸시 커밋 | 없음 | 커밋은 했는데 PR 에 없다 |
| 내 workspace 의 다른 에이전트 | 없음 | 4단계가 그 pane 들을 함께 종료한다 — 리뷰어 출력이 사라진다 |

**PR 조회에 번호를 넣지 않는다.** 번호를 넣으려면 PR 이 있다는 것을 이미 알아야 해서 "PR 이 있나"를 묻지 못한다. 번호 없이 조회하면 현재 브랜치의 PR 을 찾아 번호를 함께 준다.

**`mergeable: UNKNOWN` 을 머지 불가로 읽지 않는다.** GitHub 이 비동기로 계산해서 갓 push 한 PR 과 이미 머지된 PR 이 둘 다 `UNKNOWN` 이다. 먼저 `state` 로 가르고, `OPEN` 인데 `UNKNOWN` 이면 잠시 뒤 한 번 다시 조회한다.

**CI·리뷰가 비어 있음은 실패가 아니다.** 워크플로가 없거나 리뷰를 GitHub 에 남기지 않는 저장소에서는 항상 빈다 — 그때는 넘어간다.

**`herdr agent list` 는 다른 사람 작업까지 전부 반환한다.** `herdr pane current` 로 내 workspace_id 를 얻어 거른다.

조사 결과를 **`AskUserQuestion` 한 번으로 묶어** 승인받는다. 걸린 것이 없어도 그 사실을 적어 묻는다 — 사용자가 물을 것이 남았는지는 명령으로 알 수 없다.

## 1. PR 머지

0단계에서 얻은 번호와 머지 방식으로 `gh pr merge` 한다.

**`--delete-branch` 를 쓰지 않는다.** 머지 뒤 로컬 base 브랜치를 체크아웃하려 하는데, base 는 메인 체크아웃이 잡고 있어 어느 worktree 에서도 반드시 실패한다. 이미 실행해서 `is already used by worktree` 를 봤다면 **머지 자체는 성공해 있다** — 재시도하지 말고 아래 확인으로 넘어간다.

머지 뒤 두 가지를 확인한다 — PR 이 `MERGED` 인가, 원격 브랜치가 남아 있는가. 원격 브랜치는 `git ls-remote --exit-code` 의 **종료코드**로 판정한다(`2` 면 삭제됨). `| wc -l` 로 세면 네트워크·원격 오류도 0 줄이라 삭제와 구분되지 않는다. `deleteBranchOnMerge` 가 켜진 저장소는 이미 지워져 있으므로 남아 있을 때만 지운다.

## 2. 저장소 지침의 마감 절차

이슈 트래커 완료 전환, 결과 코멘트, 후속 이슈 생성 같은 것이 여기 온다. 지침에 없으면 이 단계는 없다. 되돌릴 수 있는 것만 여기 두고, 되돌릴 수 없는 것은 0단계 승인 질문에 미리 적는다.

## 3. pane 정리 — 기본은 생략한다

4단계가 workspace 를 통째로 닫으므로 보통 필요 없다. 리뷰어 출력을 미리 정리하고 싶을 때만 한다.

**`herdr agent stop` 은 없는 명령이다.** pane 을 닫으면 그 안의 에이전트도 함께 종료된다. `herdr agent list` 를 내 workspace_id 로 거른 뒤 `herdr pane close` 한다 — 거르지 않고 닫으면 **남의 세션을 종료시킨다.**

## 4. worktree 제거 — 실행하면 이 세션이 끝난다

`herdr worktree list --cwd "$PWD"` 에서 **`path` 가 지금 작업 중인 worktree 와 일치하는 행**의 workspace ID 만 쓴다. `--cwd` 를 빼면 현재 디렉터리가 아니라 **포커스된 workspace** 의 저장소를 반환한다 — 다른 창이 포커스돼 있으면 이 저장소 행이 아예 없다. 목록에는 메인 체크아웃과 다른 사람의 worktree 가 함께 있고, 잘못 고른 `--force` 는 그것들을 유실시킨다. 예측하지 않는다.

지우기 전에 재확인한다 — `git status` 가 비었는가, PR 이 `MERGED` 인가. **`git log origin/<base>` 로 내 커밋을 찾지 않는다** — squash 병합이면 내 SHA 는 base 에 절대 나타나지 않아 항상 "없음"이다. 커밋이 들어갔는지는 PR 의 `MERGED` 로 본다.

재확인 결과가 0단계와 같으면 되묻지 않고, 다르면 멈추고 묻는다. 0단계 승인은 "이상 없음"에 대한 승인이지 무슨 일이 있어도 지우라는 위임이 아니다.

`herdr worktree remove --workspace <ID> --force` — workspace 가 닫히면서 **이 세션도 함께 종료된다.** 반드시 마지막이다. 이 명령은 allowlist 에 넣지 않는다 — 되돌릴 수 없는 유일한 단계에 권한 프롬프트를 한 번 남긴다.

## 자주 틀리는 것

| 이렇게 한다 | 왜 |
|---|---|
| `--delete-branch` 를 쓴다 | base 가 메인 체크아웃에 잡혀 있어 반드시 실패한다 |
| 그 에러를 보고 머지를 재시도한다 | 머지는 이미 됐다. `state` 로 확인부터 |
| 저장소 설정을 보지 않고 `--squash` 를 쓴다 | squash 가 꺼진 저장소에서 거부된다 |
| `ls-remote \| wc -l` 로 삭제를 판정한다 | 오류도 0 줄이다. 종료코드를 본다 |
| `mergeable: UNKNOWN` 을 머지 불가로 읽는다 | 갓 push 한 PR 과 머지된 PR 이 둘 다 그렇다 |
| CI 실패를 확인하지 않고 머지한다 | 1단계는 되돌릴 수 없다 |
| `herdr agent stop` 을 부른다 | 없는 명령이다 |
| `agent list` 를 거르지 않고 닫는다 | 남의 세션을 종료시킨다 |
| `--workspace` ID 를 짐작한다 | 목록에 메인 체크아웃이 섞여 있다 |
| `git log origin/<base>` 로 내 커밋을 찾는다 | squash 라 SHA 가 남지 않는다 |
| worktree 를 먼저 지운다 | 세션이 끝나 나머지를 못 한다 |
| 0단계를 건너뛰고 머지한다 | 물을 기회는 그때뿐이다 |
| 이상이 없는데 중간에 확인을 구한다 | 승인은 0단계에서 받았다 |
