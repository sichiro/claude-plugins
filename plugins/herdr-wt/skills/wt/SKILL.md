# 이슈 하나 또는 묶음의 작업 자리를 준비한다

`ARGUMENTS` 의 앞쪽 토큰들이 이슈 식별자다 — 여럿이면 한 브랜치에서 함께 작업할 묶음이다. 나머지에서 `--kind` 값(`claude`·`codex` 등), `옮겨줘`(포커스 이동), `--prompt` 또는 `-p`(첫 지시를 바로 실행)를 읽는다. 기본은 `claude`, 포커스는 지금 자리에 두고, 첫 지시는 **초안**으로 넣는다 — 입력칸에 넣되 제출하지 않아, 사용자가 내용을 보고 Enter 만 누르면 시작된다. 환경이 초안을 지원하지 않으면(reference 가 정한다) 지시를 넣지 않는다.

**준비까지만 한다.** 해결 방법을 조사하지 않는다. 사용자가 그 에이전트로 직접 작업한다. 첫 지시는 이슈 본문에 적힌 것을 옮기는 일이지 코드를 조사하는 일이 아니다. 「지시해서 시작해줘」「바로 돌려줘」처럼 실행까지 맡기는 말은 `--prompt` 로 읽는다.

## 환경

herdr 는 두 가지가 있고 명령이 다르다. 1단계에서 하나로 판정하고 **그 환경의 reference 하나만** 읽는다. 아래 절차의 「reference 의 ○○ 절」은 그 파일의 절이다.

| 판정 | 환경 | reference |
|---|---|---|
| `HERDR_ENV=1` | herdr TUI | `reference/herdr-tui.md` |
| 위가 아니고 `HC_TERMINAL_ID` 가 있다 | Herdr 앱(herdr-core `hc`) | `reference/herdr-app.md` |
| 둘 다 아니다 | herdr 밖 | 알리고 중단한다 |

## 저장소 지침

`.claude/wt.md` 가 있으면 먼저 읽고, 각 단계에서 관련 지시를 따른다 — base 브랜치, 브랜치 종류, 생성 직후 실행할 것, 이슈 트래커 연동, 에이전트 정책처럼 저장소마다 다른 것이 거기 있다. 지침은 단계를 더하거나 값을 정할 뿐, **단계의 순서와 base 명시는 바꾸지 못한다.**

없으면 base 는 `develop`, 종류는 `feature`·`fix`·`docs`·`chore`, 이슈 트래커는 없는 것으로 진행한다.

## 절차

1. 위 표로 환경을 판정하고 그 reference 를 읽는다
2. 저장소 지침에 이슈 트래커가 있으면 **먼저 이슈를 조회해** 요약과 현재 상태를 얻는다 — 주제어와 7·8단계가 쓴다. 첫 지시를 지으므로 본문과 코멘트를 전부 받는다. 그 뒤 브랜치명을 `<종류>/<슬러그>-<영문 주제어>` 로 짓는다
   - **이슈가 여럿이면 전부 조회한다.** 슬러그와 에이전트 이름은 첫 이슈로 짓고, 주제어는 묶음을 아우르는 말로 짓는다
   - **종류는 이슈 유형이 아니라 변경 성격으로 정한다** — 유형이 「작업」이어도 결함 수정이면 `fix/`
   - 슬러그는 이슈 식별자에서 `-` 를 떼고 소문자로 — `MGR-135` → `mgr135`, `135` → `135`
   - **에이전트 이름은 슬러그에서 짓되 숫자로 시작하면 `i` 를 붙인다** (`135` → `i135`). 이름 규칙 `[a-z][a-z0-9_-]{0,31}` 이 숫자 시작을 거부한다
   - 주제어는 티켓을 열지 않고도 무슨 일인지 알 만큼 적는다. 종류나 주제어를 정할 근거가 없으면 **사용자에게 묻는다**
3. reference 의 「worktree 만들기」 절대로 만든다. **base 를 반드시 명시한다** — 생략하면 어딘가의 현재 HEAD 를 따라가 조용히 다른 곳에서 갈라진다
4. 저장소 지침에 생성 직후 할 일(로컬 파일 연결 등)이 있으면 여기서 한다. 실패하면 에이전트를 띄우기 전에 멈추고 보고한다
5. reference 의 「에이전트 띄우기」 절대로 띄운다. 저장소 지침에 모델이 있으면 그 값을 명시한다 — 기본값은 사용자의 `/model` 선택에 따라 바뀐다. codex 는 아래 절을 따른다. 결과로 나온 ID·주소는 **응답에서 읽고 예측하지 않는다**
6. `옮겨줘` 가 있으면 reference 의 「포커스」 절대로 옮긴다. 없으면 포커스가 지금 자리에 남았는지 같은 절대로 확인한다
7. 「첫 지시」 절대로 지시를 짓고 reference 대로 넣는다 — 기본은 초안(제출하지 않음), `--prompt` 면 바로 실행이다. 들어갔는지 화면으로 확인하고, 확인되지 않으면 무엇이 떠 있는지 보고한다. 방향을 물어야 하는 이슈면 지시를 짓기 전에 묻는다
8. 저장소 지침에 이슈 착수 절차(상태 전환 등)가 있으면 여기서 수행한다. 실패해도 9단계는 한다 — worktree 와 에이전트는 이미 준비돼 있다
9. 환경 · workspace(또는 space) ID · 경로 · 브랜치명 · 에이전트 이름이나 주소 · 이슈 번호 전부를 보고한다. 지시를 넣었으면 그 요지(방향·리뷰 행·충돌 주의)를 함께 적는다. 지침이 없어 기본값으로 진행했으면 그 사실도, codex 로 띄웠으면 훅과 저장소 지침이 걸리지 않는다는 사실도 함께 알린다

reference 에 따라 5·7단계가 한 명령으로 합쳐진다(앱은 에이전트를 띄우며 초안을 함께 넣는다). 그때도 4단계는 그 앞에서 끝내고, 첫 지시는 5단계 전에 지어 둔다.

## 첫 지시

**초안**(기본)은 사용자가 입력칸에서 읽고 Enter 를 누를 글이다. reference 가 정한 길이 안에서 한 줄로 쓴다 — 이슈를 읽으라는 말에, 본문에 없는 것(아래 3번의 답 · 6번 · 7번)만 붙인다. 아래 골격은 `--prompt` 로 바로 실행할 때 쓴다.

이슈 본문과 코멘트에 적힌 것을 에이전트가 바로 시작할 수 있는 지시로 옮긴다. 코드를 읽지 않는다. 아래 순서가 골격이고, 저장소 지침에 「첫 지시」 절이 있으면 그 값으로 채운다. 없으면 이슈 본문에서 나오는 것만 적고 빈 항목은 뺀다.

1. **읽을 것** — 이슈 번호와 본문·코멘트를 읽으라는 말. 묶음이면 전부. 코멘트가 범위를 덧붙였으면 그것도 범위임을 적는다
2. **요지** — 무엇이 어디서 어떻게 틀렸는지 두세 문장. 본문의 「문제」「원인」에서 옮긴다. 파일·함수 이름은 본문에 있는 것만 쓴다
3. **방향** — 본문의 「고치는 법」에서 정한 것. 후보가 여럿이거나 「정하지 않았다」「정할 것」이 남아 있으면 지시를 넣기 전에 `AskUserQuestion` 한 번으로 묻고 그 답을 적는다. 이것이 유일하게 남는 왕복이고 같은 호출 안에서 끝난다. 본문이 부실해 방향을 못 적으면 그 사실을 적고 에이전트가 먼저 조사하게 둔다
4. **하지 않는 것** — 본문이 범위 밖으로 둔 것과, 저장소 지침의 후속 이슈 규칙(범위 밖 결함은 이슈로 남긴다)
5. **테스트·검증** — 본문의 「검증」「테스트」와 저장소 지침의 에이전트 절(실기기가 필요한지, 어느 기기인지)
6. **리뷰·PR** — 저장소 지침의 리뷰 행 규칙으로 고른 행과 그 근거 한 줄, `Closes #n`, 끝맺음 절차(리뷰 스킬·PR)
7. **충돌 주의** — `gh pr list --state open --json number,headRefName,files` 로 열린 PR 의 파일과 본문의 「손대는 곳」「어디」를 대조한다. 겹치면 PR 번호·파일과 「PR 을 올리기 전에 base 를 가져와 푼다」를 적는다. 겹치는 것이 없으면 이 항목을 뺀다

지시는 한 메시지로 넣는다. 에이전트가 되물을 만한 것을 남기지 않는 것이 목표다 — 되묻는 왕복 하나가 이 옵션이 아끼려는 것이다.

## codex 로 띄울 때

인자에 `--yolo` 를 덧붙인다. 기본 샌드박스는 worktree 밖 쓰기를 막는데, 링크드 worktree 의 git 디렉터리는 worktree 밖에 있어 커밋조차 `Operation not permitted` 다. `--yolo` 는 `codex --help` 에 나오지 않지만 실재하는 별칭이다.

범위를 좁히려면 `--yolo` 대신 `--add-dir "$(git rev-parse --path-format=absolute --git-common-dir)"` — git 디렉터리 하나만 연다. `--path-format=absolute` 를 빼면 메인 체크아웃에서 상대경로 `.git` 이 나와 codex 가 자기 cwd 기준으로 잘못 푼다.

codex 세션에는 Claude Code 의 훅도 저장소 지침도 걸리지 않는다. 지침은 저장소 루트의 `AGENTS.md` 로 돌아오지만 훅은 돌아오지 않는다 — 훅이 강제하던 규칙은 사람이 확인한다.

## 어느 환경에서나 걸리는 지점

- 에이전트 이름은 살아 있는 것 사이에서 유일해야 한다. 같은 이슈로 두 번 부르면 먼저 목록을 본다
- **base 브랜치는 어떤 worktree 에서도 체크아웃되지 않는다** — 메인 체크아웃이 잡고 있어 git 이 거부한다. 결과는 로컬 병합이 아니라 push 후 PR 로 간다
- **메인 체크아웃의 미커밋 변경을 임의로 처리하지 않는다.** 되돌리거나 stash 하지 말고 사용자에게 묻는다
